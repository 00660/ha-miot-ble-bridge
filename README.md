# HA MiOT BLE Bridge

通过 HA 主机蓝牙，把已有雷达的存在与光照实体转发为米家“小米人体存在传感器”，型号 `xiaomi.sensor_occupy.03`，产品 ID `0x4683`。当前版本只实现该人体存在型号。ESP8266 雷达和已经丢失固件配置的雷达都可以使用，不需要改写原设备固件。

每个雷达使用独立的蓝牙 MAC 和米家绑定资料。存在变化立即转发；持续有人 2/5 分钟、持续无人 2/5/10/30 分钟是额外的自动化属性。常电设备的电量在米家协议内固定为 `100%`。没有光照来源时，仅米家内部报告 `0 lx`，不会在 HA 创建假光照实体。来源离线或状态未知时停止数据广播，取消持续时长累计；实际光照实体暂时未知时省略该属性。

## 主机要求

- Linux、BlueZ、HA 本机蓝牙适配器，以及可访问的 system DBus。HA 容器需具备访问蓝牙 HCI 的权限和 `/run/dbus` 挂载。
- 蓝牙 4.2 或更新，控制器支持 Android vendor HCI multi-adv 和每个广告实例独立的随机地址。仅有 BlueZ 软件多广告实例支持并不够。
- 控制器可用广告实例数必须覆盖雷达映射数量。当前实现面向已验证支持该能力的 QCA6174；其他适配器需要先确认能力响应。
- HA 2026.9.4 或更新。使用 HA 自带 `cryptography` 和 Bluetooth 集成的 `dbus-fast`，不需要另行安装旧 Python 或 ESPHome。

发送使用主机蓝牙的独立广告实例，保留 HA 原有蓝牙扫描。ESPHome Bluetooth Proxy 是扫描及连接代理，不能代替这里的主机广播功能。

## HACS 安装与配置

1. 在 HACS 的“自定义存储库”添加 `https://github.com/00660/ha-miot-ble-bridge`，类别选择“集成”。下载后重启 HA。
2. 在“设置 → 设备与服务 → 添加集成”中选择 `HA MiOT BLE Bridge`。
3. 先选择需要桥接的 HA 设备，再选择该设备的存在实体和可选光照实体。默认优选整体存在状态，避开 moving/still 分项。主机蓝牙适配器默认 `hci0`；已登记但暂时离线的来源实体也可以配置。
4. 在该转发设备中按“开始米家配对”，然后在米家 App 添加“小米人体存在传感器”。

同一时间只对一个目标开放可连接的配对窗口，其余已经绑定的雷达继续广播。使用“结束配对”关闭窗口，不会擦除绑定密钥。修改来源实体或重载集成同样保留已有米家身份。

“转发状态”显示未配对、配对中、已绑定、来源离线或蓝牙不可用，附带虚拟 MAC、来源实体和不含密钥的运行诊断。

绑定资料保存在 HA 配置目录的 `.storage/miot_ble_bridge.<entry_id>`，使用私有权限和原子写入。广播计数先持久化预留 1024 个号码，再使用；重启跳过剩余号码，避免同一个密钥重复使用 nonce。更换 HA 配置目录时需一并保留这些文件。

## 验证范围

首版已在 HA 2026.9.4 / Python 3.14.6 运行协议、HCI、GATT、状态订阅和持久化回归。QCA6174 的独立静态随机地址广播已通过外部蓝牙扫描捕获，主机原有扫描保留。实际米家添加依赖主机蓝牙外设连接和手机近场注册，软件回归不能替代手机绑定验证。

后续版本将沿用设备选择引导扩展上游其他模型，当前只列已实现的人体存在型号。

`0.1.1` 修正 REGISTER 时序：证书收到后先通过 `0010` 应答 `0x11`，正式绑定仍须等待云端 DID 解密和持久化；复用启动时预生成的 ECDH 密钥，避免在连接回调中再次准备。
